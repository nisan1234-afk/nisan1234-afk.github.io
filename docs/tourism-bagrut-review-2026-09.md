## חלק ג — אם הייתי בונה את זה מאפס

אלה לא "הכל אחרת". שלוש-ארבע החלטות שהיו מונעות את רוב מה שלמעלה.

### 1. תוכן = נתונים, לא HTML
כל יחידה היא קובץ אחד (`units/galil.json` או Markdown עם frontmatter): דפים, בלוקים עם מזהה קבוע, שאלות, שקופיות, תמונות, שאלות בגרות. **מנוע תצוגה אחד** בונה מזה את הדף. מה זה נותן מיד:
- עריכת מורה על מזהה קבוע, לא על "פסקה מספר 3".
- טיוטה/פרסום = שני קבצים, בלי מסד נתונים.
- ולידציה ב-CI: כל תמונה ממקור מאושר, כל דף עם שאלה, כל שאלת בגרות עם `source`.
- הוספת חבל = קובץ תוכן, אפס JS.

"ביקורת המועצה" מ-23.08 צדקה בעיקרון וטעתה בגודל: סכמה של ~10 סוגי בלוקים היא שבוע עבודה, לא רבעון. ההחלטה מ-25.08 לוותר עליה היא הסיבה שיש היום 4 דפוסי קוד.

### 2. שלב build קטן אחד
Vite (או סקריפט node של 50 שורות): `import`ים במקום העתקות, שמות קבצים עם hash (סוף ל-`?v=N`), Prettier/ESLint, ופריסה ל-GitHub Pages דרך Action. עדיין אתר סטטי, עדיין חינם.

### 3. בקאנד עם קוד בריפו
הבעיה הגדולה ביותר ב-CLAUDE.md היא "אין דרך לאמת מה פרוס". שתי דרכים:
- **להישאר ב-Apps Script** אבל עם `clasp` — `bagrut.gs` בריפו, פריסה מ-Action. זול ומיידי.
- **Firebase** — כבר בשימוש (push ב-`sw.js`). Firebase Auth נותן סשן מתמשך עם רענון טוקן אוטומטי (סוף ל-A1 ול-C4), Firestore נותן התקדמות בין מכשירים עם offline built-in (סוף ל-A4, A6), ו-Security Rules מחליפות את `protectedActions`. הבוט עובר ל-Cloud Function עם מכסה לתלמיד.

הייתי בוחר Firebase לפרויקט חדש. לפרויקט הקיים — clasp, כי זה יום עבודה.

### 4. מודל התקדמות אחד: יומן אירועים
טבלה/collection אחת: `{ student, unit, block, event, value, ts }`. אחוז התקדמות, "מה שכחתי", תובנות למורה, מיקום אחרון — הכל נגזר משאילתה, לא נשמר ב-30 מפתחות.

### 5. משחקים = 7 מנועים + נתונים
בדיוק הטבלה שכבר ב-CLAUDE.md. בונים כל מנוע פעם אחת, כל משחק הוא JSON.

### 6. בוט שמוגבל מבנית
המאמן מקבל את JSON היחידה כ-context ומקבל הוראה לענות רק ממנו. "לא ממציא" נאכף בקוד, לא במסמך. דורש טוקן, מכסה יומית, ולוג למורה של מה נשאל.

### 7. מערכת עיצוב אחת
`tokens.css` משותף להאב ולכל מקצוע. 3 נקודות שבירה (600 / 900 / 1200). Mobile-first — התלמידים בטלפון.

### 8. תיעוד מינימלי, תהליך דרך CI
`CLAUDE.md` עמוד אחד. החלטות ארכיטקטורה ב-ADR של חצי עמוד. יומן = git log. ריבוי סוכנים (Claude / B / קודקס) עובד דרך PR + CI ירוק כשער, לא דרך מדיניות בקובץ — כי מדיניות בקובץ היא בדיוק מה ש"נעקף בשקט".
